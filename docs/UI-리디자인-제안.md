# 유아식 웹앱 UI 리디자인 제안

작성일: 2026-10-31 · 상태: 디자인 제안, 앱 적용 전

## 방향: 가볍게 읽히는 식사 노트

흰색 중심의 화면, 정돈된 한글 글씨, 충분한 여백으로 메뉴 선택에 집중한다. 기존 코랄·베이지 분위기를 전면 교체한다. 귀여움은 장식 대신 자연스러운 문구에서 전달한다.

추천안은 **화이트·포레스트**다. 흰색과 차콜을 기본으로 짙은 초록을 주요 행동에만 사용한다. 비교안 **모노·리스트**는 색을 더 줄이고 검색과 목록 탐색에 집중한다. 두 안을 혼합하기보다 하나의 화면 체계로 통일한다.

## 현재 화면에서 바꿀 점

- 베이지 배경과 갈색 테두리가 화면 전체를 채운다. 흰색 바탕, 중성 회색 구분선으로 교체한다.
- 제목·메뉴·폼 라벨에 700~800 굵기가 반복된다. 크기와 간격으로 위계를 만들고 굵기는 제한한다.
- Pretendard 이름은 CSS에 선언되어 있지만, 조사한 src/public에는 폰트 로딩 선언·폰트 파일이 없다. 기기에 설치되어 있지 않으면 대체 글꼴이 표시될 수 있다. 글꼴 교체와 실제 로딩을 함께 처리한다.
- 비슷한 레시피 카드가 여러 줄 반복돼 첫 선택이 어렵다. 홈에서는 아침·점심·저녁 세 가지를 우선 제시하고 나머지는 전체 목록으로 연결한다.
- 프로필·월령·간 단계가 여러 곳에 반복된다. 프로필 문맥은 화면 상단 한 곳에 모은다. 각 레시피의 알레르기·적합성 정보는 유지한다.

## 글씨체

**SUIT Variable 한 가지**로 한글·영문·숫자를 통일한다. 폰트의 실제 인상은 시안으로 확인하고, 구현 시 WOFF2를 앱에 포함해 로컬 로딩한다. 라이선스 파일을 함께 보관하고 font-display: swap을 적용한다.

| 역할 | 데스크톱 / 모바일 | 굵기 | 행간 |
|---|---|---|---|
| 페이지 제목 | 32 / 28px | 600 | 1.3 |
| 섹션 제목 | 20 / 20px | 600 | 1.4 |
| 레시피 제목 | 18 / 18px | 600 | 1.45 |
| 본문·입력 | 16 / 16px | 400 | 1.6 |
| 버튼·메뉴 | 14 / 14px | 500 | 1.4 |
| 부가 정보·안전 설명 | 14 / 14px | 400~500 | 1.5 |

제목 자간 -0.02em, 본문 -0.01em을 시작값으로 삼는다. 제목은 단어 단위로 줄바꿈하고, 긴 메뉴명은 영역 높이가 늘어나도록 한다. 중요한 경고를 작은 보조 글씨로 밀어내지 않는다. 조리 시간과 분량 숫자는 필요할 때만 고정폭 숫자를 쓴다.

폰트 출처: [SUIT 공식 저장소](https://github.com/sun-typeface/SUIT) — UI 본문용 서체, SIL Open Font License.

## 색상

아래는 추천안의 라이트 테마 기준값이다. 화면 대부분을 흰색·중성색으로 두고, 초록은 주요 버튼·선택 상태에만 쓴다. AI 생성에 별도 보라색 브랜드를 만들지 않는다.

| 용도 | 값 | 적용 |
|---|---|---|
| 기본 바탕·표면 | #FFFFFF | 페이지·입력·메뉴 |
| 보조 표면 | #F5F7F6 | 선택 영역·내용 묶음 |
| 주요 글씨 | #202824 | 제목·본문 |
| 보조 글씨 | #66716B | 시간·월령·부가 정보 |
| 구분선 | #E3E8E4 | 목록·섹션 경계 |
| 주색 | #285C45 | 핵심 버튼·활성 표시 |
| 주색 눌림 | #1D4634 | hover·pressed |
| 주색 연한 바탕 | #EDF4EF | 선택된 재료·메뉴 |
| 주의 | #805719 / #FFF8E9 | AI 미검수·주의 안내 |
| 위험 | #A63333 / #FFF2F2 | 알레르기 충돌·오류 |

색만으로 상태를 구분하지 않는다. 선택은 체크·글씨, 오류는 설명과 연결하고 모든 조합은 실제 화면에서 대비를 확인한다. 다크 테마는 별도 검토 후 적용한다. 대화 시안은 호스트 테마에 맞춰 대응 색을 사용한다.

## 화면별 변화

| 화면 | 새로운 구성 | 핵심 행동 |
|---|---|---|
| 홈 | 간결한 인사와 프로필 → 적용 중인 제외 조건 → 오늘의 세 끼 → 냉장고 재료 진입 → 간식 | 오늘 먹을 메뉴 선택 |
| 재료 | 큰 검색 입력 → 선택한 재료 → 추천 결과. 저장은 보조 버튼, AI 생성은 결과 다음에 배치 | 재료 선택 후 추천 확인 |
| 전체 레시피 | 검색을 최상단에 배치. 식사/간식·시간을 먼저 노출하고 상세 조건은 접기 | 검색·필터·즐겨찾기 |
| 상세 | 제목 → 시간·월령 → AI 미검수·알레르기 → 분량·재료 → 조리 순서 → 보관·출처 | 분량 조절·조리 시작 |
| 조리 모드 | 현재 단계에 집중, 큰 본문과 타이머, 이전/다음 행동 분리 | 한 단계씩 조리 |
| 기록 | 작은 월간 달력 + 날짜별 텍스트 목록. 평가·반응은 문구로 표시 | 먹은 메뉴 기록 |
| 마이 | 아기 정보·알레르기·계정 설정을 명확한 섹션으로 분리 | 프로필 수정 |
| 로그인·가입 | 동일한 글꼴·색상, 좁은 단일 열 폼, 오류를 해당 입력 아래 표시 | 계정 진입 |

홈 세 끼는 기존 데이터의 식사 구분을 사용한다. 적합한 메뉴가 부족하면 있는 만큼만 표시한다. 같은 메뉴를 반복하거나 임의 레시피로 채우지 않는다. 홈 카드에는 메뉴명·조리시간·식사 구분·알레르기 유발 성분을 남긴다. 월령이나 간 단계의 주의가 있으면 추가로 표시한다.

적용 중인 알레르기 제외 조건은 중성 정보 줄로 표시할 수 있지만, 실제 충돌·새 이상 반응·월령 초과는 눈에 띄는 경고로 유지한다. '안전한 레시피', '검증 완료'처럼 사람의 검수나 안전을 보장하는 표현은 쓰지 않는다.

## 공통 디자인 규칙

- 데스크톱: 상단 내비게이션, 콘텐츠 최대 폭 1120px, 좌우 여백 32~48px. 큰 사이드바를 없애고 본문을 중앙에 배치한다.
- 모바일: 좌우 20px, 카드 한 열, 하단에 홈·재료·레시피·기록·마이. 현재 메뉴는 아이콘과 글씨로 함께 표시한다.
- 간격은 4·8·12·16·24·32·48px. 섹션 간 40~48px, 내용 안 12~16px을 기준으로 한다.
- 카드보다 구분선을 우선 사용한다. 카드가 필요한 추천 메뉴는 연한 표면 또는 얇은 테두리 중 하나만 사용한다.
- 입력·버튼 반경 8px, 카드 12px, 작은 라벨 4px. 모양 통일보다 역할별 구분을 우선한다.
- 한 섹션의 주요 채움 버튼은 하나. 보조 행동은 테두리 버튼이나 텍스트 링크다.
- 아이콘은 같은 선 굵기의 단색 SVG로 통일한다. 장식 이모지·그라데이션·가짜 음식 사진·카드 그림자는 사용하지 않는다.
- 실제 음식 사진이 준비되지 않은 현재는 글씨 중심으로 설계한다. 추후 사진 도입은 출처·품질·누락 상태까지 정한 뒤 별도 결정한다.
- 즐겨찾기는 44px 이상 터치 영역과 선택 상태를 가진다. 키보드 포커스는 명확하게 유지한다.
- 빈 결과에는 필터 해제·재료 변경을, 오류에는 재시도·다음 행동을 제공한다. AI 생성 중에는 중복 요청을 막고 실패 이유와 횟수 복원 결과를 실제 상태에 맞게 표시한다.

## 구현 순서와 완료 기준

### 기본 뼈대

폰트 실제 로딩, 중성색·초록 토큰, 화면 폭·간격·상단/하단 내비게이션부터 변경한다. 완료 증거: 폰트 네트워크 로딩과 실제 적용 확인, 홈 데스크톱·모바일 비교. 다음 단계 조건: 작은 화면에서 메뉴와 긴 제목이 겹치지 않는다.

### 기능 구현

홈 세 끼 우선 구성, 재료 검색과 생성 행동 구분, 목록·상세·기록 구조를 적용한다. 완료 증거: 기존 추천·저장·즐겨찾기·조리·기록 동작 확인. 다음 단계 조건: 새로운 배치에서도 각 기능과 안전 정보에 접근할 수 있다.

### UI·접근성

타입 크기·버튼·입력·경고·빈 상태·로딩을 공통화한다. 완료 증거: 실제 대비, 키보드 이동, 화면낭독기 이름·상태, 44px 터치 영역 점검. 다음 단계 조건: 320px 및 글자 200%에서 읽기와 조작이 가능하다.

### 요구사항·버그·엣지케이스 검토

긴 메뉴명, 여러 알레르기, 적합 메뉴 없음, 프로필 전환, AI 실패, 오프라인, 폰트 로딩 실패를 확인한다. 완료 증거: 기능 회귀 결과와 주요 화면 캡처. 최종 변경사항·제한사항을 함께 기록한다.

## 시안 범위와 결정 사항

대화의 시안은 두 방향을 비교하기 위한 예시 콘텐츠다. 필터와 즐겨찾기는 시안 안에서만 동작하며 실제 계정·추천 결과와 연결되지 않는다. 추천안은 화이트·포레스트이며, 모노·리스트는 많은 레시피를 한 번에 훑는 사용을 더 중시할 경우의 대안이다.

이번 산출물은 개선안과 시안이다. 실제 앱의 스타일·기능·환경 설정은 이 제안 작업에서 변경하지 않았다. 시안의 자동 테마 대응과 실제 앱의 다크 테마 구현을 동일한 완료 상태로 보지 않는다.
