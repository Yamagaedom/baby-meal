# 「오늘 뭐 먹지, 아가?」 UI 개선 검토서
**주제:** "AI 티"가 나는 UI 요소 제거 (① 전 컴포넌트 라운드 처리 ② 의미 없는 아이콘)
**검토일:** 2026-10-31 / **대상:** http://localhost:3000 (Next.js, Tailwind) / **검토 방식:** 실제 기능 사용 + 계산된 스타일 측정 + 소스 확인

---

## 0. 한 줄 결론

문제의 원인은 "예쁘게 만들려는 선택"이 모든 곳에 균일하게 적용된 것입니다. 둥근 정도에 위계가 없고(전부 둥긂), 아이콘이 정보가 아니라 장식으로 쓰입니다(거의 모든 라벨 앞에 이모지). 두 가지 모두 **토큰/공용 컴포넌트 몇 개를 고치면 앱 전체가 한 번에 바뀌는 구조**라서 수정 비용은 낮습니다.

---

## 1. 검토 범위 (직접 사용해 본 기능)

| 화면 | 직접 해본 것 |
|---|---|
| 홈 `/` | 추천 로딩, 전체/식사/간식 탭, 카드 목록, "잘 먹은 메뉴" 빈 상태 |
| 재료로 찾기 `/ingredients` | 빠른 칩 3개 선택, 선택 해제 UI, 추천 실행(30건), AI 생성 박스, "내 냉장고에 저장" |
| 레시피 `/recipes` | 필터 6종 확인, 이름 검색("주먹밥"), 즐겨찾기 추가 |
| 레시피 상세 `/recipes/[id]` | 분량 조절, 재료 체크, 조리 모드(풀스크린), 먹었어요 기록 저장(이상 반응 체크 포함), 신고 영역 |
| 기록 `/logs` | 날짜별(캘린더) / 메뉴별 누적 / 입맛 리포트 3개 탭 |
| 마이 `/my` | 프로필 목록, 프로필 추가 폼(알레르기 19종), 계정 관리, 탈퇴 영역(열람만) |
| 모바일 (390px) | 홈 + 하단 탭바 |
| 소스 | `globals.css`, `ui/Button·Badge·Chip`, `AppHeaderNav`, `RecipeCard`, `HomeRecommendClient` 등 |

미확인: 로그인/회원가입/비밀번호 재설정/온보딩 화면은 로그인 상태라 직접 열어보지 못했고, 소스 상 동일 컴포넌트를 쓰는 것으로만 확인했습니다.

## 2. 측정 결과

### 2-1. 라운드
브라우저에서 배경/테두리/그림자가 있는 요소의 `border-radius`를 화면별로 집계했습니다.

| 화면 | 박스 요소 | 알약형(pill) | 16px 이상 큰 라운드 | 8~15px | 8px 미만 |
|---|---|---|---|---|---|
| 홈 | 97 | 70 | 17 | 1 | 0 |
| 재료로 찾기(결과 후) | 301 | 233 | 39 | 1 | 0 |
| 레시피 | 1027 | 769 | 154 | 1 | 0 |
| 기록 | 48 | 8 | 37 | 1 | 0 |
| 마이 | 26 | 15 | 6 | 1 | 0 |

(나머지는 반경 0인 구분선·래퍼)
- **둥근 요소 중 8px 미만이 한 개도 없습니다.** 각진 요소가 없으니 둥근 것이 "선택된 스타일"이 아니라 "기본값"처럼 보입니다.
- 토큰 스케일이 `10 / 14 / 20 / 24px` 4단계뿐이고 최소값이 10px입니다. (`globals.css`)
- 공용 컴포넌트 기준: Button `rounded-xl/2xl`, Chip `rounded-2xl`, Badge `rounded-full`, 카드 `rounded-2xl`, 패널 `rounded-3xl`, 입력/셀렉트는 사실상 알약형.

### 2-2. 아이콘(이모지)
- 소스상 이모지/기호 사용 약 **140곳** (정규식 근사치). 컴포넌트 25개 중 대부분에 존재.
- **렌더링 기준:** 레시피 목록 한 화면(151개 카드)에서 이모지 문자 **약 750개**, 재료 추천 결과 화면 약 190개, 홈 약 70개.
- 이모지는 OS 폰트로 그려져서 Windows에서는 3D 스타일(Fluent)로 나옵니다. 앱의 따뜻한 플랫 톤과 맞지 않고, OS마다 모양이 달라집니다.
- 접근성 측면: 대부분 `aria-hidden` 처리되어 있어 스크린리더 문제는 없습니다. 문제는 **시각적 노이즈**입니다.

## 3. 이슈 A. 모든 컴포넌트가 둥근 문제

### 3-1. 눈에 보이는 증상 (스크린샷에서 확인)
1. **카드 → 카드 안의 칩 → 칩 안의 배지**가 전부 둥글어서 겹겹이 알약이 쌓입니다. (홈/재료/레시피 카드 상단 배지 3~5개)
2. **입력창·셀렉트·검색창이 전부 알약형.** 레시피 필터는 셀렉트 6개 + 입력 + 체크 + 버튼이 줄줄이 알약이라 폼처럼 보이지 않고 칩 모음처럼 보입니다.
3. **기록 캘린더의 날짜 칸이 알약형.** 캘린더는 격자(직각)가 읽기 쉬운 컴포넌트인데 날짜 셀이 타원이 되어 정렬감이 사라집니다.
4. **탭/세그먼트 컨트롤**(전체·식사·간식, 날짜별·메뉴별·입맛리포트)이 알약 안의 알약.
5. **알레르기 체크 19개**(마이 > 프로필 추가)가 각각 알약 박스. 목록성 입력인데 한 칸 한 칸이 버튼처럼 보입니다.
6. 큰 컨테이너(24px)와 작은 요소(알약)의 곡률이 달라서, **중첩 시 안쪽/바깥쪽 곡선이 맞지 않는** 부분이 있습니다. (예: 재료 선택 영역 패널 안의 칩)

### 3-2. 왜 AI 티가 나는가
- 곡률이 "역할"이 아니라 "분위기"로 정해졌습니다. 사람이 설계한 UI는 보통 요소 종류에 따라 반경이 달라지고(입력 4~6px, 버튼 6px, 카드 8px, 아바타만 원형), 구분이 필요한 곳에는 직각이 남습니다.
- 알약형은 "친근함"을 만드는 가장 쉬운 선택지라 생성형 UI에서 가장 흔한 패턴입니다. 유아식 서비스라는 맥락 때문에 더 과해졌습니다.

### 3-3. 개선안

**원칙:** 둥글기는 3단계로 제한하고, 알약형은 "정말 둥근 것"(아바타, 상태 점, 토글)에만 남긴다.

| 요소 | 현재 | 제안 |
|---|---|---|
| 페이지 섹션/카드/패널 | 16~24px (`2xl`, `3xl`) | **8px** (테두리 1px, 그림자 제거 또는 최소화) |
| 버튼 | 12~16px | **6px** |
| 입력/셀렉트/텍스트영역 | 알약형 | **6px** |
| 배지(상태 라벨) | 알약형 | **4px** 또는 **2px** (태그 느낌) |
| 선택 칩(재료 빠른 선택, 알레르기 체크 등) | 16px | **6px**, 선택 시 배경색만 변경 |
| 탭/세그먼트 | 알약 안의 알약 | 직각 밑줄 탭 또는 **6px** 세그먼트 |
| 캘린더 날짜 셀 | 알약형 | **0~2px** 격자 + 1px 선 |
| 모달/다이얼로그 | 24px | **8px** |
| 체크박스/라디오 | 기본 | 체크박스 **3px**, 라디오 원형 유지 |
| 아바타/상태 점/토글 | - | 원형 유지 (유일한 예외) |

**토큰 변경 (예):**
```css
--radius-xs: 2px;   /* 배지, 캘린더 셀 */
--radius-sm: 4px;   /* 배지, 체크박스 */
--radius-md: 6px;   /* 버튼, 입력, 칩 */
--radius-lg: 8px;   /* 카드, 패널, 모달 */
/* --radius-xl 제거, rounded-3xl / rounded-2xl / rounded-full 사용 금지 (예외: 아바타·토글) */
```

**구현 포인트**
- 공용 컴포넌트 `ui/Button · Badge · Chip · Input · Select · Tabs · Modal · Stepper`의 `rounded-*` 클래스만 먼저 바꿔도 대부분 해결됩니다.
- 개별 화면에 `rounded-3xl`, `rounded-2xl` 등이 직접 박혀 있어 (RecipeDetailClient 34곳, IngredientSearchClient 15곳, MealLogsClient 15곳) 이 파일들은 개별 수정이 필요합니다.
- `bg-[#fbf4ec]`처럼 색상이 hex로 하드코딩된 곳이 많아서 (AppHeaderNav, RecipeCard, HomeRecommendClient 등) 이번 작업에서 토큰 변수로 함께 정리하면 이후 유지보수가 쉬워집니다.
- 현재 포커스 링이 `border-radius: 4px`를 강제로 지정하고 있으니 (globals.css), 버튼 반경을 바꾸면 포커스 링도 `inherit`로 맞춰 어색함을 방지하세요.
- 터치 타겟 `min-h-11`(44px)은 접근성 기준이므로 **반경을 줄여도 높이는 유지**합니다.

## 4. 이슈 B. 의미 없는 아이콘 문제

### 4-1. 판단 기준
아이콘이 있어야 하는 경우: ① 텍스트 없이 쓰이는 버튼(즐겨찾기, 닫기, 타이머), ② 경고/위험처럼 **의미를 즉시 전달**해야 하는 경우, ③ 모바일 하단 탭바처럼 공간이 좁은 내비게이션.
없어도 되는 경우: 이미 텍스트가 같은 뜻을 말하는데 앞에 붙은 장식.

### 4-2. 전수 점검 결과

| 위치 | 현재 | 판단 | 제안 |
|---|---|---|---|
| 사이드바 메뉴 5개 (🏠🥕📖📝👶) | 라벨 + 이모지 | 장식 | 데스크톱은 **아이콘 제거**(텍스트만, 활성은 좌측 바/굵기). 모바일 탭바만 **단색 라인 아이콘 1세트**로 통일 |
| 카드 배지: 식사 🍲 / 간식 🍌 | 이모지 + 텍스트 | 장식 | 텍스트만 |
| 카드 배지: **AI 레시피 🤖** | 모든 카드에 동일하게 표시 | **정보량 0** (전 레시피가 AI 생성이라 구분 효과 없음) | 카드에서 제거. 고지는 **상세 화면 상단 안내문**으로 이미 충족 |
| 카드 배지: **무염 💧** | 모든 카드 동일 | 프로필 설정과 항상 같음 → 중복 | 카드에서 제거. 아기 프로필 간과 **다른** 레시피에만 표시 |
| 카드 배지: 시간대 ✨ ("아침 식사", **"추가 추천"**) | 별 아이콘 | 장식 + "추가 추천"은 의미 불명 | 아이콘 제거. "추가 추천"은 삭제 |
| 카드 조리시간 ⏱ | 이모지 | 약한 장식 | "16분" 텍스트만 또는 작은 시계 라인 아이콘 1개 |
| 매칭 "67% 일치" ✨ | 장식 | | 아이콘 제거, 숫자 강조 |
| **즐겨찾기 버튼** ☆/★ + 텍스트 | 카드 한 줄 전체 차지 | 아이콘은 **기능적**이나 큰 알약 버튼이 카드 높이를 키움 | **카드 우상단 아이콘 버튼 1개**로 축소 (aria-label 유지) |
| 알레르기 🏷 | **작은 깨진 사각형으로 렌더링됨** (스크린샷 확인) | 장식 + 렌더 문제 | 아이콘 삭제, "알레르기 유발 성분:" 텍스트 |
| 월령 상한 안내 ⚠ | 경고 | **기능적(유지)** | 라인 아이콘 + 색상으로 통일 |
| 탭: ✨ 전체추천 / 🍲 식사만 / 🍌 간식만 | 장식 | | 아이콘 제거 |
| 기록 탭: 📅 / 📖 / 📊 | 장식 | | 아이콘 제거 |
| 홈 "다른 메뉴 보기" 🔄 | 버튼에 이모지 | 약한 의미 | 텍스트만 (원하면 라인 아이콘 1개) |
| 홈 섹션 "😋 호랑이가 잘 먹은 메뉴" | 제목 앞 이모지 | 장식 | 제거 |
| 기록 > 입맛 리포트: 😋 / 🥦 / 🙅 / ✨ 섹션 제목 | 장식 | | 제거 |
| 냉장고 저장 🧊 | 버튼 앞 | 장식 | 제거 |
| AI 생성 박스 🤖, 식사/간식 토글의 🍲🍌 | 장식 | | 제거 |
| 상세: "기본 카테고리 일러스트 (저작권 보호를 위해 …)" 박스 | 이모지 + **개발자용 설명문이 사용자에게 노출** | 가장 AI/프로토타입스러운 요소 | 영역 자체 삭제하거나 실제 사진·삽화 있을 때만 표시 |
| 상세: 조리 모드 🍳, 타이머 ⏱ | | 타이머는 기능적 | 🍳 제거. 타이머는 라인 아이콘 유지 |
| 상세: 난이도 ★ | 별 1개 | **의미 불명** (별 1개가 쉬움인지 알 수 없음) | "난이도: 쉬움/보통" 텍스트로 |
| 상세: 반응 선택 😋😐🙅 | 감정 선택 | **기능적**이나 OS 이모지 | 유지하려면 직접 만든 3종 SVG, 아니면 텍스트 3단계(잘 먹음/보통/안 먹음)로 충분 |
| 상세: 신고 ⚠ | 경고 | 유지 가능 | 라인 아이콘으로 통일 |
| 토스트/에러/빈 상태 | 이모지 다수 (Toast 4, FeedbackStates 2, 404/에러 페이지 등) | 장식 | 텍스트 + 상태색. 에러만 라인 아이콘 |
| PWA 오프라인 배너, 복구 코드 카드 | 이모지 | 장식 | 제거 |
| 탈퇴 영역 ⚠ | 위험 | 유지 | 라인 아이콘으로 통일 |

### 4-3. 정리 규칙 (디자인 시스템에 명문화)
1. **텍스트 라벨 앞에 아이콘을 붙이지 않는다.** (단, 모바일 하단 탭바 예외)
2. **이모지를 UI 요소로 쓰지 않는다.** 필요하면 SVG 라인 아이콘 한 세트만(Lucide 등, 1.5px 선, 16/20px).
3. 아이콘이 허용되는 곳은 ① 아이콘 단독 버튼 ② 경고/오류/성공 상태 ③ 모바일 탭바 ④ 타이머.
4. 한 카드에 **배지는 최대 2개**(예: 식사/간식 + 시간대, 또는 경고). 현재 카드당 4~6개.
5. 정보가 모든 항목에서 같으면 항목마다 반복하지 말고 상위 헤더에서 한 번만 말한다. (무염, AI 생성)

## 5. 같이 보인 "AI 티" 요소 (이번 두 항목과 함께 고치면 효과가 큰 것)

| # | 증상 | 근거 | 제안 |
|---|---|---|---|

## 8. 수용 기준 (구현 후 확인용)

**라운드**
- [ ] `rounded-2xl`, `rounded-3xl`, `rounded-full`이 아바타/토글/상태 점 외에는 소스에 남아 있지 않다
- [ ] 같은 화면에 서로 다른 반경이 **최대 3종**만 쓰인다 (예: 4 / 6 / 8px)
- [ ] 입력·셀렉트는 알약형이 아니다
- [ ] 기록 캘린더 날짜 셀이 직각 또는 2px 이하
- [ ] 버튼/입력 높이는 여전히 44px 이상 (접근성 유지)
- [ ] 포커스 링이 요소 반경과 어긋나지 않는다

**아이콘**
- [ ] 레시피 목록(151건) 화면에서 이모지 문자 수 **0** (현재 약 750)
- [ ] 홈에서 이모지 문자 수 **0~2** (경고 정도만) (현재 약 70)
- [ ] 텍스트 라벨 앞 장식 아이콘이 없다 (모바일 탭바 예외)
- [ ] 아이콘이 남는 곳은 아이콘 단독 버튼 / 경고·오류 / 탭바 / 타이머뿐이다
- [ ] 카드당 배지 최대 2개
- [ ] 아이콘 단독 버튼에는 `aria-label`이 있다 (기존 접근성 유지)

**안전·법적 고지는 유지**
- [ ] 상세 화면 상단 "AI 생성 · 사람 미검수" 안내 유지
- [ ] 알레르기 유발 성분 표시, 월령 초과 경고 유지 (아이콘은 줄여도 **텍스트·색상 대비는 유지**)

## 9. 기능 사용 중 확인한 사항

- 정상 동작: 추천 새로고침/탭 전환, 재료 선택→추천(30건 매칭), 이름 검색, 즐겨찾기, 분량 조절, 조리 모드, 먹었어요 저장(저장 후 목록·캘린더·입맛 리포트에 즉시 반영, 이상 반응도 기록에 표시), 프로필 추가 폼.
- 확인 못한 것: "내 냉장고에 현재 재료 저장" 클릭 후 성공 표시를 스크린샷에서 확인하지 못했습니다(토스트가 이미 사라졌거나 표시가 없을 가능성). 저장 피드백이 충분한지 별도 확인이 필요합니다.
- **검토 중 만든 테스트 데이터:** (1) 연어단호박주먹밥 즐겨찾기, (2) 2026-10-31 점심 먹은 기록 1건(메모 "UI 검토용 테스트 기록", 이상 반응 "발진"), (3) 냉장고 재료 감자·당근·두부 저장 시도. 실제 사용 데이터라면 정리가 필요합니다. (기록 삭제 UI는 확인하지 못했습니다.)

## 10. 구현 인계 시 참고 (Codex 등 코딩 에이전트용)

1. 이 앱의 Next.js는 일반 버전과 다르므로(`AGENTS.md` 경고) 코드 수정 전에 `node_modules/next/dist/docs/`를 먼저 확인할 것.
2. 작업은 **토큰 → 공용 UI 컴포넌트 → 화면별 직접 클래스 → 이모지 제거** 순서로 하면 되돌릴 일이 적습니다.
3. 기존 E2E 테스트(`tests/e2e/ui-a11y-pwa.spec.ts` 등)가 버튼 이름이나 이모지 텍스트에 의존하는지 확인하고, 이모지 제거로 접근 가능 이름이 바뀌지 않게 `aria-label`을 유지할 것.
4. `/dev/ui` 쇼케이스 페이지가 있으니 반경/배지 변경 후 이 페이지로 먼저 확인하면 전 화면을 돌지 않아도 됩니다.
5. 변경 후 `/recipes`와 `/ingredients`(결과 표시 상태)에서 위 2-1, 2-2 측정을 다시 돌려 Before/After를 비교하면 개선이 수치로 남습니다.
