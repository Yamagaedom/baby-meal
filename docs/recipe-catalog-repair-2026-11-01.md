# 레시피 데이터 복구 · 2026-11-01

## 원인

- 운영 DB 60개, 로컬 DB 242개로 데이터가 일치하지 않았다.
- 로컬 242개 중 33개는 E2E·mock 중복 메뉴다. 숫자를 맞추기 위해 업로드하지 않는다.
- 운영 52개 메뉴의 역할이 UNKNOWN이었고, 출처 확인 레시피는 8개뿐이었다. 주간 식단에서 식사로 선택되는 MAIN은 3개였다.
- 일부 메뉴의 연령 배열은 상위 단계에서 불필요하게 제외되었다. 최소 연령은 유지하고 이후 지원 단계까지 검증했다.

## 복구 기준

1. 원문을 조회할 수 있고 원 작성자의 재료 설명이 해당 조합을 뒷받침해야 한다. 기관 홈페이지 주소·검색 결과 링크만으로 확인 처리하지 않는다.
2. YouTube 공식 API로 공개·처리 완료 상태와 원문 설명을 조회했다. 879개 공개 영상 중 37개 원문의 재료 조합을 선별했다. 영상 전체를 시청하거나 임상 적합성을 인증했다는 의미는 아니다.
3. 원문을 그대로 복제하지 않는다. 앱에서 조정한 분량·식감·재료·양념을 응용으로 명시한다. 신규 메뉴의 육수는 물로 바꾸고 선택 간장·치즈를 제외했다. 조리법·이름·조리도구·보관 안내도 함께 수정했다.
4. 운영 식재료 사전으로 재료 매핑, 최소 월령, 알레르기, 나트륨, 총량·단위, 보관·조리 필수 필드를 재검증한다. 알레르기 필터나 무염 상한을 완화하지 않는다.
5. 기존 레시피를 삭제하거나 ID를 교체하지 않는다. 숨김 처리된 레시피를 활성화하지 않는다. 기존 즐겨찾기·식사 기록·후기를 보존한다.

## 결과

- 기존 60개 보완 + 신규 83개(식사 73·간식 10) = 143개.
- 기존 34개의 출처를 보완했다. 출처 확인 레시피는 125개다. 나머지 18개는 확인 처리하지 않으며 주간 자동 구성 대상에서 계속 제외된다.
- 로컬 배치 150개 중 중복 조합 1개와 원문 근거가 부족한 66개는 복구에서 제외했다.
- 식사·반찬·간식·주식 역할을 분리했다. 반찬을 완전한 한 끼로 자동 선정하지 않는다.
- 공식 USDA 참고 식품 매핑을 60종으로 확대했다. 대체 품종·부위는 mappingNote에 기록했다. 제품별 성분을 알 수 없는 육수·가공품·양념은 미확인으로 남겼다.

알레르기·조리 시간·선택 재료 등 추가 조건을 적용하면 후보 수가 줄어든다. 위 수치는 해당 조건을 적용하지 않은 기준이다.

## 영양 계산 수정

- 근거 없는 식품군 평균값과 출처가 연결되지 않은 수동 영양값을 제거했다.
- 상세 화면의 식재료 사전에 slug와 성분표를 전달하고, 주간 영양 추정기와 같은 계산을 사용한다.
- 조리 회분을 바꾸어도 1회분 영양은 동일하다. 원본 레시피의 baseServings로 나눈다.
- 선택 재료를 제외하고, 중량·성분 미확인은 null로 유지한다. 일부 값만 있으면 부분 합계와 누락 재료를 표시한다.
- 근거가 불분명한 보편적 '1끼 권장량 충족률' 표시는 제거했다. 주간 영양 체크의 연령별 하루 기준은 유지한다.

## 검증·복구 방법

- 원본 백업: .local-data/recipe-production-before.json, recipe-local-before.json (Git 제외).
- 공개 원문 메타데이터: .local-data/recipe-source-evidence.json (Git 제외). 공개 API 키는 출력·저장하지 않는다.
- 배포되는 콘텐츠와 원문 ID·확인 시각·설명 해시: src/data/recipe-catalog-repair.json.
- catalog:prepare는 로컬 백업으로 변경 명세를 생성한다. DB를 수정하지 않는다.
- catalog:sql은 명세로 트랜잭션 DML 파일을 생성한다. DB 실행은 별도 관리 작업이다.
- catalog:check는 localhost DB의 pg_temp 테이블에 운영 백업을 복제해 같은 DML을 검증한다. 운영 데이터는 수정하지 않는다. 모든 기존 ID 보존, 143개·출처 확인 125개, 중복 실행 시 개수 불변을 확인한다.
- 기존 메뉴가 백업 이후 수정되거나 비활성화되었으면 적용을 중단한다. 같은 버전을 다시 실행하면 건너뛴다. 사용자 기록을 지우는 reseed·임시 공개 관리 API를 사용하지 않는다.
- 전체 단위·DB 회귀 테스트 73개 및 타입 검사 통과. 별도 작업 폴더의 의존성 junction 때문에 기본 Turbopack 로컬 빌드는 경로 제한에 걸렸고 Webpack 프로덕션 빌드는 통과했다. 운영 배포에서는 기본 Turbopack 빌드를 확인한다.
- 저장소 전체 lint에는 기존 seed·AI 저장 코드의 any, 후기 컴포넌트의 effect 관련 오류 4개가 있다. 이번 수정 파일의 lint는 별도로 확인한다.
