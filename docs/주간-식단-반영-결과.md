# 주간 식단 계획 반영 결과

작성일: 2026-11-01

## 반영한 흐름

홈의 이번 주 식단 → 3개 화면·5개 질문 → 7일 초안 → 메뉴 교체·유지 및 일정 변경 → 식단 확정 → 조리·준비 완료 → 음식 재고 입고 → 제공·먹은 기록 및 재고 출고.

- 하단 메뉴: 홈 / 레시피 / 식단 / 기록 / 마이. 재료로 찾기는 레시피에 묶되 기존 주소와 홈 바로가기를 유지했다.
- 재료 화면의 `이 재료로 일주일 구성`은 선택 재료를 전달한다. 상세의 `식단에 담기`는 해당 메뉴를 추가할 수 있게 연결한다.
- 주간 초안과 문답 조건은 아기별 DB에 저장한다. 다음 계획에서 이전 조건을 재사용할 수 있다.
- 집에서 준비할 끼니, 평일 점심 외부 식사, 간식 0~2회, 먼저 쓸 재료, 장보기 허용, 준비 방식, 조리일, 시간·도구·기피 재료, 우선순위를 반영한다.
- 자동 구성은 알레르기·월령·간 단계와 출처 상태를 확인한 기존 후보를 사용한다. 사용자 선택 재료, 재고, 선호·최근 기록, 식품군·확인 가능한 영양 성분, 조리 부담과 반복을 고려한다.
- 메뉴를 직접 추가해 밥·반찬 등을 한 끼에 함께 담을 수 있다. 날짜 이동·외부 식사·계획 제외·메뉴 유지·나머지 재추천을 지원한다.

## 조리량·재고의 의미

먹을 회분과 만들 회분을 분리했다. 만들 양은 조리일·레시피별로 지정하고 기존 1~5회분 계산을 재사용한다. 그보다 많은 양은 여러 조리 묶음으로 나눈다. 장보기 양은 식단 칸 수가 아닌 조리 묶음의 재료량으로 합산한다. 원재료 보유 여부만으로 장보기 수량을 0으로 만들지 않는다.

초안은 실물 재고를 바꾸지 않는다. 확정하면 예약하고, 조리 완료 시 실제 수량을 입고하며, 제공할 때 수량을 출고한다. 예를 들어 1회분을 꺼내 반만 먹어도 출고는 1회분이다. 재시도는 같은 입고·출고를 중복 처리하지 않는다.

음식은 식사/간식, 냉장/냉동, 조리일·사용 기한별로 나눈다. 수동 등록·꺼내기·폐기·수량 정정·보관 변경을 지원한다. 재고 예약·출고는 계정 행 잠금과 트랜잭션, 이벤트 식별자로 보호한다. 다른 아기의 계획과도 중복 예약하지 않는다. 식단 수정·보관은 예약을 풀고 실제 음식은 남긴다.

레시피 없는 음식도 재료·보관 상태·기한을 사용자가 직접 확인하면 식단에 담을 수 있다. 이 경우 자동 영양·알레르기 적합 판정은 하지 않으며, 제공 이력은 식단과 재고에 남는다. 레시피에 연결되지 않은 음식에 가짜 recipeId를 만들어 먹은 기록에 넣지 않는다.

## 영양·출처 데이터

- [USDA SR Legacy 공식 다운로드](https://fdc.nal.usda.gov/download-datasets/)에서 식품 36종을 매핑했다. 원본 ZIP SHA-256은 `b80817294b8850530aaedf2e515c02593b1824f763a0ff356e5c2081643e6fd0`이다.
- `scripts/prepare-nutrition-data.py`로 공식 CSV에서 동일한 성분 부분집합을 재생성할 수 있다. 식품 코드·영문 식품명·자료 버전·100g 기준을 함께 저장한다.
- 열량, 탄수화물·단백질·지방, 철·칼슘·나트륨·식이섬유를 실제 제공 회분으로 합산한다. 재료·성분이 누락되면 부분 추정 또는 계산 불가로 표시한다. `약간`을 임의 중량으로 바꾸지 않는다.
- 2025 한국인 영양소 섭취기준의 유아 연령별 단백질·철·칼슘 권장섭취량과 나트륨 충분섭취량을 참고값으로 제시한다. [원문 요약본](https://health.seoulmc.or.kr/uploadFiles/2025_%ED%95%9C%EA%B5%AD%EC%9D%B8%EC%98%81%EC%96%91%EC%86%8C%EC%84%AD%EC%B7%A8%EA%B8%B0%EC%A4%80_%ED%99%9C%EC%9A%A9.pdf)의 PDF 13·19·20쪽을 확인했다.
- 어린이집·외식과 입력하지 않은 음식은 미포함으로 안내한다. 계획의 추정값으로 실제 섭취량·영양 충족을 단정하지 않는다. 표준 식품과 국내 제품·품종·조리 후 성분 차이도 표시한다.
- [식약처 COOKRCP01 공개 원문](https://www.foodsafetykorea.go.kr/api/newDatasetDetail.do?svc_no=COOKRCP01)의 실제 10·11·16·17·32번을 근거로 무염·부드러운 질감의 응용 메뉴 5개를 추가했다. 원문과 달라진 재료·조미·분량을 설명한다. 원문을 검수한 것과 아기별 안전성을 보장하는 것은 구분한다.
- 밥·우유·플레인요거트 3개는 표준 성분 자료에 연결한 단순 음식이다. 이 출처가 조리 원문을 뜻하지 않음을 설명한다. 밥 하나를 자동으로 완전한 한 끼로 배치하지 않는다.
- 기존 레시피는 자동으로 출처 확인 상태를 부여하지 않는다. 알려진 가상 링크는 INVALID로 분류하고 점수를 0으로 내린다. 일반 기관 홈페이지를 검증된 레시피 출처로 대체하는 AI 폴백을 제거했다. 오래된 캐시도 확인 상태가 없으면 검증된 출처로 표시하지 않는다.

자동 추천 후보는 위의 확인된 항목부터 시작한다. 모든 기존 레시피가 출처 확인을 마친 것은 아니며, 기존 자료 전체의 성분 매핑도 완료된 것은 아니다. 활용하지 못한 선택 재료와 빈 메뉴는 화면에서 설명한다. 공식 한국 식품 데이터 확대와 추가 메뉴의 원문 확인은 이후에도 계속할 콘텐츠 작업이다.

## 구현 단계와 검증 증거

| 단계 | 반영 결과 | 확인한 증거 |
|---|---|---|
| 기본 뼈대 | 계획·항목·조리·재고·예약·이력 모델, 아기·계정별 조회 | 추가 마이그레이션과 Prisma 생성·타입 검사 |
| 기능 구현 | 재료 기반 구성, 회분, 장보기, 재고, 기록, 영양 추정 | 단위·DB 통합 테스트 66개 통과 |
| UI·접근성 | 짧은 문답, 날짜 선택, 메뉴 편집, 음식 관리, 상태·오류 안내 | 모바일 브라우저 흐름과 가로 넘침·심각 접근성 오류 검사 통과 |
| 요구사항·버그·엣지케이스 검토 | 중복 출고·동시 예약·권한·불완전 영양·수동 음식 처리 | DB 테스트 및 실제 브라우저에서 확인 |

전체 테스트 중 로컬 Prisma 개발 프록시가 연결을 종료한 문제가 있었으며 데이터 파일을 유지한 채 재시작한 후 13개 파일·66개 테스트가 통과했다. 기존 CSS 로더의 Windows 빌드 오류는 Tailwind 공식 PostCSS 구성으로 교체해 해결했다.

운영 빌드는 Vercel 기존 baby-meal 프로젝트에 연결한다. `db:deploy`는 초기 테이블의 존재 여부와 원래 컬럼을 확인한 뒤 필요한 초기 기준 기록과 추가 마이그레이션을 수행한다. 신규 데이터 적재는 재실행해도 같은 메뉴를 중복 생성하지 않는다. 마이그레이션은 기존 레시피·사용자 데이터를 삭제하지 않는다.
