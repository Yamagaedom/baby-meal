# 화이트·포레스트 UI 적용 결과

적용일: 2026-10-31 · 기준: [UI 리디자인 제안](./UI-리디자인-제안.md)

## 기본 뼈대

- SUIT Variable WOFF2와 라이선스를 앱에 포함하고 모든 화면에서 사용하도록 연결했다. 폰트가 브라우저에서 로드되는지 확인했다.
- 흰색·중성 회색·짙은 초록을 공통 색상에 적용하고 보라색 AI 강조를 중성색으로 바꿨다. 경고와 오류 색은 구분해 유지한다.
- 입력·버튼 8px, 카드 12px, 작은 배지 4px로 정리하고 굵은 글자 사용을 줄였다.
- 데스크톱 사이드바를 상단 메뉴로 교체하고 본문 최대 폭을 1120px로 제한했다. 모바일 하단 내비게이션과 프로필 전환은 유지한다.

## 기능 구현

- 홈은 기존 추천 결과의 아침·점심·저녁을 우선 보여주고 전체 레시피 및 재료 찾기로 연결한다. 나머지 메뉴를 홈에 반복 표시하지 않는다.
- 재료 검색을 빠른 선택보다 위에 배치하고, AI 생성 영역은 기존 레시피 결과 다음으로 이동했다. 재료 저장과 추천, AI 사용량 표시를 유지한다.
- 레시피 목록은 검색을 필터보다 먼저 배치한다. 상세는 메뉴 제목과 기본 정보 다음에 AI 미검수·의료 고지와 월령 경고를 배치하고, 이후 알레르기와 재료를 보여준다.
- 공통 색상과 글자 굵기를 상세·조리·기록·프로필·인증 등의 화면에도 적용했다. 실제 충돌과 월령 경고, 알레르기 표시, 안전 검증 동작은 유지한다.

## UI·접근성

- 카드 배경과 간격을 단순화하고 제목·조리 시간·알레르기를 쉽게 구분하도록 했다.
- 320·360·390·768·1280px 화면과 200% 글자 크기를 확인했다. 주요 화면의 axe critical/serious 위반은 없었다.
- 제목·버튼·즐겨찾기·하단 메뉴의 이름과 상태, 키보드 이동 및 터치 영역을 기존 검사로 확인했다.
- 새 글꼴을 서비스워커 캐시에 포함하고, 네트워크를 끊은 상태에서 캐시된 글꼴과 즐겨찾기 레시피를 불러오는지 확인했다.

## 요구사항·버그·엣지케이스 검토

- 최종 프로덕션 빌드·TypeScript·ESLint 통과.
- 단위·통합 테스트 55개 통과. 브라우저 전체 테스트 11개 통과 후 상세 고지 위치를 조정하고 관련 브라우저 테스트 4개를 다시 통과했다.
- 이후 오프라인 글꼴 제공 경로를 추가하고 PWA 테스트를 별도로 통과했다.
- 추천·즐겨찾기·알레르기 차단·재료 저장·분량 조절·기록·오프라인 보관함을 분리된 테스트 DB에서 확인했다. AI 생성 테스트는 모의 응답을 사용했다.
- 테스트 서버 반복 실행 중 가입 제한에 도달해 임시 서버를 재시작한 후 전체 검사를 완료했다. 사용자의 실제 DB나 배포 환경은 사용하지 않았다.
